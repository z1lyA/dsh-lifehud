# ADR-0001：形态与数据层

- 日期：2026-11-01
- 状态：已接受
- 影响范围：整个项目的第一版

## 背景

用户想做一个"打开就能掌控一整天"的个人工作台，载体是 DSH（DeepSeek Harness）。
在此之前有一份旧架构文档（`个人数字管家-架构.md`），以事件表 + 规则引擎 + 健康数据为核心。经评估该文档与用户的真实目标偏离：它写的是一个健身追踪后端，而用户要的是"生活操作系统（Life OS）"的入口。

## 决定

### 决定 1：主轴是「掌控」，不是「行动」

- **掌控**：一屏看完今天（态势感知）——这是第一屏。
- **行动**：委托 agent 做事——v1 只保留"一句话录入"与"一条建议的确认"。
- 理由：掌控的反馈是即时的，行动的反馈延迟且依赖信任积累；且"行动"能力 DSH 已具备，不必自造。

### 决定 2：载体 = DSH 插件（外壳），但数据层必须与 UI 解耦

否决的选项：
- 纯 DSH 内做（UI 与数据耦合）——将来换手机端就得重写。
- 自写前端 + DSH 只当 agent 引擎——v1 要多写一个前端，看不到东西的时间太长。

采用：UI 第一版画在 DSH 插件里（`client.js` + `host` 路由），数据通过**本地 HTTP 接口**提供。
手机端（PWA）推迟到 v2，届时只换壳、不换数据层。

### 决定 3：两个接口面，共用一份数据访问代码

| 消费者 | 协议 | 理由 |
|---|---|---|
| 看板 UI | HTTP + JSON（`/api/*`） | UI 不会"决定调用工具"，它只要确定的 URL 和字段 |
| DSH 里的 agent | MCP（`/mcp`） | 模型需要工具清单 + 自然语言选择 |

否决：只做 MCP（UI 显示不出东西）、只做 HTTP（让模型 curl 并解析 JSON，脆弱且烧 token）。

### 决定 4：数据存本机，SQLite 一个文件

- `data/butler.db`（SQLite）+ `data/*.md`（目标、偏好、布局配置）。
- 备份 = 复制文件。
- 不上 Postgres / 不上云：v1 没有手机端，不需要 24h 在线。
- **升级到云的路径**（将来）：所有读写经过一个 core 模块、不写 SQLite 特有语法、时间统一存 UTC 展示层再转时区 → 换 Postgres 约一天。真正的成本不在数据库，在"手机怎么安全访问"（鉴权、TLS、备份）。

### 决定 5：技术栈 = TypeScript 一体

DSH 插件本身就是 TS/JS（前端 bundle + host 端 Node），接口层同语言意味着同一套工具链、同一进程模型、不跨语言调试。
否决：Python 数据层——多一个运行时、多一套部署；真需要统计库时 Node 调 Python 子进程即可。

### 决定 6：任务数据只读 NowTree，不改它一行

- 直接只读打开 `nowtree.sqlite` 的 `transactions` 表，取 `status='active' AND show_in_next=1 AND deleted=0`，按 `time_slot` 分早/午/晚。
- 理由：SQLite 支持多进程只读；零风险；当天可用；能验证"我到底会不会在工作台里看任务"。
- 写回（勾选完成）推迟到 v1.5，届时才决策"给 NowTree 加 API"还是"勾选跳回 NowTree"。
- 否决：把 GTD 逻辑重写进工作台——会把三个月的项目变成六个月。

### 决定 7：第一版不做自有数据，只做聚合（**这是本 ADR 里最脆弱的决定**）

用户主动降级了健康/训练/饮食记录，理由是"健身专业度还不够，现在做是自己给自己造负担"。
后果：v1 三张卡片（今日任务 / 天气+时钟 / 最近会话）全部是**只读聚合**，没有任何数据由本系统产生。
风险：纯聚合看板留存率低（同类项目普遍"装好、配好、不再打开"），且系统不会因为被使用而变聪明。
缓解（已提给用户，待确认）：加一个**"每日一句话"最小写入**（一行文本），成本极低，但让系统第一次有了只属于自己的数据，也是后续所有判断的第一个数据点。

## 后果

- ✅ 一周内可以看到东西；不需要写前端；不需要服务器。
- ✅ 数据层与 UI 解耦，换壳成本低。
- ⚠️ 工作台的价值几乎完全押在"今日任务"卡片上——它是唯一每天都变的内容。
- ⚠️ 「最近会话」卡片要读 DSH 自己的会话存储，属于与平台内部结构的耦合，DSH 升级可能失效（已派人核查最稳做法）。
- ⚠️ DSH 插件依赖内部服务（`webServer.register`、`ctx.sessions` 等），DSH 是 RC 版本、nightly 自动更新 → 插件要锁版本、写测试、升级前备份 `$DSH_HOME`。

## 什么情况下会推翻本 ADR

1. 连续两周打不开这个页面 → 说明"掌控"不是真需求，或卡片选错了（重新 grill）。
2. 发现必须写回任务才用得下去 → 决定 6 作废，转 v1.5。
3. 手机上想用的欲望 > 桌面上 → 决定 2/4 作废，转 PWA + 云端数据层。
4. 需要真实的健康判断 → 决定 7 作废，重启事件表 + 规则引擎（旧文档的正确部分）。
