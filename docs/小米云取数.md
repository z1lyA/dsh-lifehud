# 小米云取数（体重）—— 方法留档

> 写这份文档的原因：v1.1.0 上线后，桌面上的 `mx80-data/README_方法说明.md`
> 与那批 Python 探针脚本会被删掉（见体重卡方案的 §9）。**会话过期后怎么重新登录**这件事
> 不能跟着一起消失，所以把长期有用的事实搬进仓库。
> 文档只写方法与路径，**不写任何凭据值**。

## 1. 数据从哪来

小米 App（米家）把 MX80 体脂秤的每次称重写进云端的「设备自定义数据」，
不在任何标准 miot-spec 属性里。取数组合是插件逆向出来的固定值：

| 项 | 值 |
|---|---|
| 端点 | `POST https://api.io.mi.com/app/user/get_user_device_data` |
| 设备号 `did` | **自动发现**：`POST /home/device_list` 里 `model` 带 `scales` 的那台（如 `yoda.scales.mx80`），结果缓存进体重库的 `meta` |
| 请求体 | `{did, uid, type:'weight', key:'bodyInfo', time_start:0, time_end:<现在秒>, group:'raw', limit:1000}` |
| 时间单位 | **秒**（传毫秒会返回空数组，这是最容易踩的坑） |
| 返回 | `{code:0, result:[{uid,did,type,key,time,value}]}`，`value` 是 **JSON 字符串**，含 40 个字段（`weight` / `bmi` / `fatRate` / `createTime` / `weightId` …） |

想手工看一眼设备列表（比如自动发现失败时）：

```bash
node spike/probe-mi-cloud.mjs <mi-session.json 路径> --devices
#   did=blt.3.xxxxxxxx  model=yoda.scales.mx80  name=…  online=false
#   然后：node spike/probe-mi-cloud.mjs <会话> --did <那台秤的 did>
```

也可以在配置里显式写 `miDid` 覆盖自动发现。

`weightId` 是毫秒时间戳。**一定要当文本处理**：`1786238280146` 一旦被当成浮点写成
`1786238280146.0`，就没法当主键去重了（v1.1.0 的 `toWeightRow()` 已经转成字符串）。

## 2. 鉴权：会话文件 + RC4 签名

### 会话文件
默认读 `<dataDir>/mi-session.json`（`dataDir` 默认 `~/.dsh/lifehud`；可用 `miSession` 配置项指到别处）：

```json
{ "userId": "…", "serviceToken": "…", "ssecurity": "…", "saved_at": "…" }
```

- 位置在**仓库之外**，`.gitignore` 已把 `mi-session.json` 挡住。**不要 `git add` 它。**
- 插件**只读**这个文件，从不写回、不复制、不打印。
- 三个字段都是凭据：`serviceToken` 相当于登录态，`ssecurity` 是签名密钥，`userId` 是账号 id。

### 请求签名（对齐 `micloud.miutils`，插件里已用纯 JS 重写）
```
nonce         = base64( 8 字节随机 ‖ 当前分钟数的最短大端字节 )
signed_nonce  = base64( sha256( base64decode(ssecurity) ‖ base64decode(nonce) ) )
data          = {"data": "<业务参数的 JSON 字符串>"}
rc4_hash__    = base64( sha1( "POST&/user/get_user_device_data&data=<data>&" + signed_nonce ) )
每个值        = base64( RC4( base64decode(signed_nonce), 值 ) )     ← 详见下方"1024 字节"
signature     = base64( sha1( "POST&路径&data=…&rc4_hash__=…&" + signed_nonce ) )
body          = { data, rc4_hash__, signature, ssecurity, _nonce=nonce }   ← form-urlencoded
```
请求头/ Cookie 装作米家 Android 客户端：`MIOT-ENCRYPT-ALGORITHM: ENCRYPT-RC4`、
`x-xiaomi-protocal-flag-cli: PROTOCAL-HTTP2`、`content-type: application/x-www-form-urlencoded`、
Cookie 里塞 `serviceToken` / `yetAnotherServiceToken` / `userId` / `locale` 等。

响应**可能是密文**：不以 `{` / `[` 开头时，用同一个 `signed_nonce` 做 RC4 解密再 `JSON.parse`。

> **RC4 的 1024 字节**：pycryptodome 的 `ARC4` 在 `micloud` 里是先加密 1024 个零字节
> （丢弃）再加密正文，所以密钥流必须推进 1024 字节。Node 24 的 OpenSSL 3 **默认不带 rc4**
> （`createCipheriv('rc4')` 抛 `digital envelope routines::unsupported`），
> 因此 `plugin/index.js` 里是二十行的纯 JS RC4（`rc4Init` / `rc4Apply`）。

## 3. 本地镜像

落库到 `weightDb`（默认 `<dataDir>/lifehud-weight.db`，`dataDir` 默认 `~/.dsh/lifehud`）：

```sql
weight(weight_id TEXT PRIMARY KEY, ts INTEGER, date TEXT, weight_kg REAL,
       measured_at TEXT, raw_json TEXT)   -- raw_json 存全部 40 字段，留给 v2 人形图
meta(key TEXT PRIMARY KEY, value TEXT)    -- lastSyncAt、自动发现的 miDid
```

- 每次同步按 `weight_id` **upsert**，重复拉取不会重复插入。
- 曲线口径是「最近**有数据的** 7 个测量日」：同一天多称几次只留最后一次，日期可以不连续。
- 小米云**只读**，LifeHud 唯一的可写状态就是这个镜像库和 `lifehud-settings.json`。

## 4. 会话过期了怎么办

会话过期不是文件损坏，是小米侧失效（没有公开的固定 TTL；实测 2026-11-06 签发的
token 至少活到 2026-11-09）。表现为：云调用返回 `code≠0`（`70016` / `-1`），
卡片显示红字「小米云会话已过期，请重新登录」，并继续用本地缓存画曲线 —— 历史不丢。

重新生成会话文件需要**重新登录一次**（要手机确认）。已知可行路径：

1. 用开源工具 [Xiaomi-cloud-tokens-extractor](https://github.com/PiotrMachowski/Xiaomi-cloud-tokens-extractor)
   扫码/账密登录，它会打印 `userId` / `serviceToken` / `ssecurity`，
   按 §2 的格式写进 `mi-session.json`，**放到 `<dataDir>/mi-session.json`**（或 `miSession` 指的位置）。
2. 上一轮用的是自己写的一次性登录脚本（会打印验证 URL，手机点确认），产物同样是这个 JSON；
   脚本本身是临时产物，没有随仓库发布。

> 诚实说明：上面第 1 条是通用做法，**本次会话没有用它重新登录过**（现有 token 一直有效），
> 所以具体到某个版本的界面步骤，以工具当时的 README 为准，不要凭记忆操作。

换完会话文件**不需要**重装插件：下一次 `/lifehud/api/weight?force=1` 就会重新打云。

## 5. 隐私边界（别越线）

- 只访问小米官方域名（`api.io.mi.com`），凭据不出本机。
- 会话文件与体重数值都不进 git、不进日志、不打印明文。
- 不写回任何外部数据源：不改设备状态、不 `setDeviceData`、不动小米账号的任何设置。
- 不做自动登录、不保管小米密码（这是产品决策，不是技术限制）。
