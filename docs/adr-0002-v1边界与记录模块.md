# ADR-0002：v1 边界与心智记录模块

- 日期：2026-11-04
- 状态：已接受（部分待验证）
- 前序：ADR-0001（形态与数据层）
- 覆盖：第 2–6 轮 grill 的全部决定（Q11–Q23）

## 背景

ADR-0001 定下了形态（DSH 插件外壳 + 解耦数据层 + 本机 SQLite + TS）。
此后用户主动做了一次重要的范围收缩：**把健康/训练/饮食记录整体降级**——理由是"健身专业度还没到，现在做是自己给自己造负担"。同时提出了一个新的记录需求（视频收获、事件思考、行为准则），并暴露了两个真问题：**分类分不清**、**记录要不要过模型**。

## 决定

### 决定 8：数据层只装三样东西（Q11）

- 缓存（天气、会话摘要）、配置（`dashboard.yml`）、自有记录。
- **不定义任何业务 schema**。没有事件表、没有目标表、没有干预表。
- 理由：v1 没有自有事实，建大 schema 是空转；但不建库也不行——天气 API 有限流、读 DSH 会话目录慢，裸打源头会让页面变慢。

### 决定 9：不做「每日一句话日记」（Q12）

- 否决：它要求每天产出一段"有意义的话"，是日课，有产出义务。
- 用户的真实用法是**收集箱**（像微信文件传输助手）：想起来才扔，允许无意义。
- 而收集箱这件事 **NowTree 的 inbox 已经在做**，v1 不重复造。

### 决定 10：最近会话卡片 = 标题 + 相对时间 + 工作区（Q13）

- 不需要摘要、不需要未读数、不需要分组。
- "正在进行中"标记做成**开关，默认关**（官方 `ctx.agents.get(id)?.status === 'running'`，5 行）。
- 数据来源已核实：`sessionQuery.listSessions()` + `sessionProjectionCache.cachedSnapshot()`（零 IO 取标题）+ `workspaceRegistry`。点击跳转需在插件客户端调 `uiWorkspace.openSession()`（非 URL，搬到 PWA 后会失效）。

### 决定 11：天气卡 = 一天温度曲线 + 一句 agent 生成的建议（Q14）

- 纯数字的天气卡是装饰（手机上下滑就有）；加一句"该怎么办"之后才有掌控感。
- 这是 v1 里**唯一"AI 在场"**的地方，也是将来"判断层"的原型。
- 数据源：**Open-Meteo**（无需注册、无需 API key、免费；已实测返回逐小时 `temperature_2m` 与 `precipitation_probability`，支持 `timezone=Asia/Shanghai`）。
- 否决：和风/高德（要 key + 实名）；纯数字卡（无信息增量）。

### 决定 12：页面形态 = 多卡片首页，但为"早晨 3 分钟"排序（Q15）

- 首页是**容器形态**，早晨是**信息排序**，两者不冲突。
- 顶栏放日期 + 时钟（**不占卡片位**）。
- 首屏三卡：今日任务（最大）/ 天气曲线 / 最近会话；下面可滚动。

### 决定 13：卡片清单配置化（Q16）

- `data/dashboard.yml` 声明"有哪几张、什么顺序、什么参数"。
- 注意边界：配置只解决"哪些卡、什么顺序、什么参数"，**新类型的卡仍需写渲染代码**。

### 决定 14：项目名 `dsh-lifehud`（Q17 / Q19）

- 文件夹、仓库、插件包名统一为 `dsh-lifehud`，中文叫「抬头」。
- 备选 `lifeconsole` 被否决：`console` 在开发者语境里默认指命令行，会持续造成误解。
- 核查：GitHub 上 `lifehud` 同名仓库 12 个、最大 1 星且 2024 年停更；npm 未占用。

### 决定 15：心智记录模块 v1 不做，先 V0 纯 markdown 试跑（Q18 / Q23）

- V0：`mind/mind.md` + `mind/principles.md`，一个文件、三行格式、一个可空标签。
- 观察一到两周，再回答三个问题：会不会记？用不用标签？回不回看？
- 理由：跟 NowTree 的 inbox 是同一道题——"记录的地方本来就有，只是没在用"。先验证习惯，再写代码。

### 决定 16：记录**不走模型**（token 成本 + 改写风险）

- 算账：一次"记一条"在 DSH 里 ≈ 5 万 token 输入（含系统提示与工具清单），约 0.005–0.05 元/条；按每天 3–5 条，约 3–30 元/月。
- 钱不是主要问题。**主要问题是模型会改写原话**——"抄写"这件事不需要智力，却多了一个会润色、会补因果、会把"我不太确定"改成"我认为"的中间人。三个月后翻回去，分不清哪句是自己说的。
- 分工原则：**抄写不过模型，加工才过模型。**
  - 记一条：纯前端 → `POST /api/note` → 追加 md（0 token）
  - 整理一条/提炼准则：对话 + agent（这才是该花钱的地方）

### 决定 17：这个模块和 NowTree 是两种东西（不是任务的另一种形态）

| | NowTree（意图） | 心智记录（信念） |
|---|---|---|
| 指向 | 未来的某个动作 | 行为倾向 |
| 生命周期 | inbox → active → **completed** | 没有"完成"，只有被强化 / 修正 / 丢弃 |
| 会变短吗 | 会（做完就没了） | 不会（只会变长） |
| 价值来源 | 被**消费** | 被**回看** |
| 核心状态 | status / 截止 | confidence / evidence / 用过几次 |

**推论：信念库唯一可行的维持方式是"回看"，不是"整理"。** 整理是给"会变短的东西"设计的。

### 决定 18：分类数量由"回看时做什么"决定，不由内容决定

- 回看时只有三个动作：**照做**（方法）、**提醒自己**（准则）、**想起当时的自己**（素材）。
- 所以最多三类，而且**不是三个文件夹，是同一个文件里的一个可选标签**。
- 一条尺子：**一个分类只有在"装了 10 条以上、且每周都会看一次"时才值得存在。**
- 被否决的方案：上一版 agent 给的 7 文件 / 6 分类 / 5 步决策树 / 6 字段模板。设计不差，但 25 条内容摊到 6 类 = 每类 4 条，且每次记录要过决策树——**写入成本会杀死记录行为本身**。
- 准则的产生：**不是攒，是提炼**。从记录里提 3–5 条，不是写 15 条；一周一次，agent 提 0–2 条候选，用户只做"接受 / 改一句 / 驳回"。

## 后果

- ✅ v1 范围很窄：三张卡片 + 一个配置 + 一条只读查询。
- ✅ 心智记录在 v1 之前就能开始（零代码），避免了"先造工具再用工具"。
- ⚠️ v1 几乎没有自有数据（记录推迟到 V0 验证之后），仍接近"只读聚合器"——靠"今日任务"撑住每日打开的理由。
- ⚠️ 心智记录一旦验证通过，它会是第一个需要"写"的功能，届时才决定 `POST /api/note` 的形态与鉴权。

## 什么情况下会推翻

1. V0 一周只记了 0–1 条 → 决定 15/16/18 全部作废，心智记录不进 lifehud。
2. 回看一次都没发生 → "时不时看看"是伪需求，回看卡片不做。
3. 天气卡那句建议被证明是废话（"今天 8–16℃，注意保暖"）→ 决定 11 退回纯数字卡，且说明 v1 无 AI 在场。
4. 发现必须写回任务才用得下去 → ADR-0001 决定 6 作废，转 v1.5。
