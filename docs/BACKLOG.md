## 1. 空闲强度的展示（v1.2 详情页）

- **现状**：`idle_seconds` 已按 `0-10 / 10-60 / 60-180 / 180+` 四档作为第三条流落库，
  `/hud` 的 `idle.levels` 也给出了 24h 内每档分钟数；页面还没消费。
- **为什么现在不做**：专注卡只有一格，塞四档空闲强度会挤掉应用排行；它更适合放在 1.2 的详情页
  和「应用占比 / 切换次数 / AFK 比例」一起展示。
- **建议做法**：详情页加一张「今天有多专注」的小图（四档堆叠条或环形），数据直接读 `idle.levels`；
  可选把「最长专注段」和「空闲占比」并排放。
- **验收**：页面在深/浅主题下可读；数据与 `capture.db` 独立复算一致（扩展 `probe-focus`）；
  不影响专注卡现有布局。

## 2. 检查更新「自动查 / 后台查」（可选）

- **现状**：刻意手动（用户 2026-11-12 的选择）；Host 的 `readUpdate()` 已支持单飞，加定时器成本很低。
- **为什么现在不做**：产品决策成本更高——启动查一次？每天一次？发现新版用 Toast 还是徽标？需要用户先定。
- **验收**：先确认联网频率与提醒方式；再把「自动检查」做成设置开关（默认沿用当前的手动）。

## 3. 专注卡「关掉 = 真停采」

- **现状**：设置里的开关只影响展示，Host 仍在采集；真正停采需要 Client → Host 通道。
- **建议做法**：`POST /lifehud/api/capture {enabled}`（记得 loopback 鉴权），Host 侧 `stopCapture` / `startCollector`。
- **验收**：关掉后 `capture.running=false`、进程表无残留 powershell；重新打开能恢复采样；
  页面开关文案与实际行为一致。

## 明确不做

- **重写已 push 的历史提交**（评审 S10）：需要 force push，违反「不自行 push / 不改已推送历史」。
  提交粒度的问题只在以后的提交里注意，不回改历史。
